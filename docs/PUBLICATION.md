# Публикация копии и отдельная среда Codex

## Подготовка Git и закрытого репозитория

Владелец создаёт пустой **Private** reading-journal-android-public без README, LICENSE и .gitignore. До загрузки проверить отсутствие refs/коммитов, права записи и private=true, fork=false. Новый каталог и git init, без копирования .git, clone/mirror или переноса объектов прежнего проекта. Для автора и коммиттера использовать точный noreply из настроек GitHub Settings → Emails; адрес не угадывать и не заменять личной почтой.

Первый коммит main содержит только очищенную документацию. Ветка codex/ui-01-design-system-navigation добавляет приложение, тесты, CI и актуальные отчёты, затем создаётся Draft PR в main. Оба bootstrap-коммита помечаются [skip ci], до разрешения приватных запусков не делать. Проверить автора/коммиттера всех коммитов, независимый root без родителей, отсутствие прежних commits/tags/refs, отсутствие CI runs. Перечень файлов и суммы сверить до push. Если noreply или репозиторий недоступен, сохранить локальный комплект и статус BLOCKED; ничего не имитировать.

## Перевод в Public — выполняет владелец

1. Открыть именно новый репозиторий, проверить имя, очищенные файлы, историю и Draft PR. Существующий архивный проект оставить без изменений.
2. Проверить результат аудита и ограничения; не переносить прежние логи/артефакты. Публичность новой копии не является разрешением раскрыть архив.
3. GitHub → Settings → General → Danger Zone → Change repository visibility → Public. Прочитать предупреждения GitHub и подтвердить решение самостоятельно. Агент видимость не меняет.
4. После подтверждения Public отдельно разрешить свежие автоматические проверки на стандартных GitHub-hosted Ubuntu runners. Проверить тарифные условия GitHub для выбранного аккаунта/runner; larger runners не использовать.
5. В новой среде Codex разрешить пустой активационный коммит без [skip ci] в рабочую ветку. Он не меняет приложение. Quick PR CI проверяет Head; затем Codex по явному разрешению владельца переводит существующий Draft PR в Ready через CLI/API для полного запуска. Это разрешение на тесты, не на merge.
6. Проверить все Build/lint/JVM/API 26/35/36, Full acceptance, checksum APK и срок доступности артефактов. Если финальный отчёт потребовал нового docs-коммита, quick может быть docs-only, но перед окончательной приёмкой Codex самостоятельно повторно запускает полный цикл на итоговом Head в пределах полученного разрешения. Не создавать бесконечную цепочку отчётных коммитов: точный финальный SHA/ссылки можно зафиксировать в PR после проверки.
7. Применить предложенную защиту main и ограничения внешних PR из [CI.md](CI.md) самостоятельно. Приёмка UI-01, merge и следующая задача требуют отдельных решений.

## Отдельная среда Codex со смартфона

1. В настройках интеграции GitHub разрешить Codex доступ к **новому** репозиторию. Не расширять доступ без необходимости.
2. Создать отдельную облачную среду и выбрать reading-journal-android-public. Не переиспользовать checkout/.git/кэши проекта как способ переноса истории. Открывать рабочую ветку UI-01 и сверять Base/Head нового PR.
3. Setup: JDK 17.0.21+9, platform-tools, platforms;android-37.0, build-tools;36.0.0, cmdline-tools 16111833; зависимости через Gradle Wrapper 9.9.1. SDK задавать локальными переменными/неотслеживаемым local.properties. Не коммитить proxy, credential helpers, truststore, токены и локальные пути.
4. Доступ к Google Maven/Android SDK, Maven Central, Gradle distributions/plugins и GitHub настраивать через интерфейс среды. Использовать поставленные proxy/CA с проверкой TLS. Секреты в чат не передавать; для публичной сборки приватные runtime secrets не нужны, запись GitHub авторизуется штатной интеграцией.
5. Прочитать AGENTS и семь основных документов, проверить git status/новую историю/noreply, запустить локальные проверки по README. Сначала подготовить и проверить конфигурацию; публикацию среды выполнять только по явному разрешению владельца.
6. Для полной матрицы использовать GitHub CI после разрешения, а при локальном эмуляторе — SDK images API 26/35/36 и KVM при наличии. Недоступность эмулятора обозначать NOT RUN, не подменять результат.
7. После каждой задачи останавливаться. Назначение новой среды не разрешает UI-02/UI-03.

## Окончательная UI-01-проверка после публикации

Новый полный CI на итоговом Head: Build, lint, минимум 3 JVM и по 10 Android-тестов API 26/35/36, XML guard, debug APK, SHA-256 файла и диагностические снимки. APK versionName 0.1.1-ui01 / versionCode 2, тот же applicationId. Перенос не изменяет код/тесты/дизайн. Сверить подпись с установленной сборкой; риск несовместимости описан в [A55](acceptance/UI-01-GALAXY-A55.md).

Владелец уже подтвердил повторную проверку шести визуальных исправлений на A55. Этот факт не означает формальную приёмку UI-01; новая сборка и её установка/подпись проверяются отдельно. Для принятия записать решение владельца, сохранить PR необъединённым до отдельного разрешения merge.

## Постоянный автоматизированный процесс

По явному заданию владельца Codex самостоятельно ведёт рабочие ветки и PR, выполняет push, запускает необходимые проверки, анализирует CI и исправляет ошибки в согласованном scope. Результат — APK, SHA-256, ссылка на артефакт и итоговый отчёт. Безопасно доступные CLI/API операции не перекладываются на владельца. При ограничении платформы агент указывает конкретную причину и необходимое действие без запроса секретов в чате. Merge и следующее задание требуют отдельных явных разрешений; продуктовые требования, дизайн и ручная приёмка не меняются.
