# Два уровня Android CI

## A — быстрые проверки

`Android quick` реагирует на opened/synchronize/reopened Pull Request и push только в main. Фильтра рабочей ветки UI-01 нет: будущие задания используют тот же механизм. Push в ветку PR не создаёт второй запуск.

Проверяется scope путей текущей задачи, новый манифест документации и локальные ссылки, регрессии CI-скриптов, whitespace. Для изменения кода, ресурсов, Gradle, CI или любого неизвестного пути выполняются debug Build, lint, все JVM-тесты и сборка AndroidTest APK. Загружаются APK с SHA-256 самого APK и разрешённые результаты; retention 7 дней.

Пропуск Android разрешён только для непустого набора изменений семи корневых Markdown и Markdown/TXT внутри docs. Сравнение использует before→head текущего synchronize, поэтому правка отчёта после кода не пересобирает весь Android только из-за совокупного diff PR. Scope при этом проверяется по всему base→head PR. Удаление/переименование кода учитывает обе стороны через --no-renames. Неизвестный/отсутствующий before, пустой delta, изменения workflow или нераспознанные файлы означают сборку. Полный запрос никогда не пропускает сборку.

`Quick checks` явно пишет **Full Android matrix: NOT RUN**. Он не является доказательством итоговой приёмки.

## B — полная проверка перед приёмкой

`Android full` запускается событием **ready_for_review**, когда сам владелец переводит Draft PR в Ready. Это отдельное явное разрешение, агент сам статус не меняет. Проверки owner/public выполняются до сборки. Для повторного запроса владелец возвращает PR в Draft и снова переводит в Ready; после изменения Head нужен новый полный запуск.

Второй вход — workflow_dispatch того же полного workflow, только владельцем. Он станет доступен штатно после появления workflow в main; до merge docs-only main его не содержит. Dispatch не считается автоматически PR-проверкой: результат должен относиться к точному Head и требуемому PR check. До первого merge использовать PR ready_for_review.

Полный workflow всегда выполняет:

| Проверка | Минимум UI-01 |
|---|---|
| Scope / docs / CI-script tests / git diff --check | Все обязательные |
| Debug APK / lint / AndroidTest APK | Все, без отключений |
| JVM | ≥3, 0 failures/errors/skips |
| Compose API 26 | ≥10, полный suite, 0 failures/errors/skips |
| Compose API 35 | ≥10, полный suite, 0 failures/errors/skips |
| Compose API 36 | ≥10, полный suite, 0 failures/errors/skips |
| XML validator | Отсутствующие/нулевые/неконсистентные результаты — FAIL |
| APK checksum | SHA-256 app-debug.apk, не ZIP |
| Артефакты | APK/metadata/checksum, JUnit/lint, синтетические кадры и свежий instrumentation log; 30 дней |

Приёмочный check **Full acceptance** существует только в полном workflow. В нём always-gate отвергает failure/cancelled/skipped/отсутствующий job. Это позволяет требовать отдельный check на main: быстрый запуск его не создаёт и не подменяет. Полный suite не фильтруется по классам и не повторяет assertions ради зелёного результата.

Пороги и API находятся в .github/ci-policy.json. Они не могут уменьшаться относительно base и ниже 3/10/API 26/35/36. Для следующей разрешённой задачи обновляются task/scope и минимумы по её требованиям. Путь в разрешённой области сам по себе не доказывает отсутствие новой продуктовой функции: review владельца обязателен.

## Экономия и безопасность

Оба входных workflow используют одну concurrency group на номер PR: новый quick synchronize отменяет устаревший full, новый full заменяет незавершённый quick. Полный workflow включает собственные быстрые проверки/Build. Сборка идёт до матрицы, чтобы ошибка lint не запускала эмуляторы. Таймауты: preflight 5 минут, Build 25, каждый emulator job 40, итоговый gate 2. Используется только стандартный ubuntu-24.04.

Все сторонние Actions закреплены по commit SHA; версии JDK/SDK/CLI/emulator и зависимостей сохранены. Gradle cache для PR и эмуляторов read-only; main может обновлять dependency cache. Configuration-cache encryption secrets, приватные токены и пользовательские credentials не используются. Checkout persist-credentials=false, permissions только contents: read; pull_request_target отсутствует. Автоповтор тестов отсутствует; подтверждённые инфраструктурные сбои расследуются отдельно.

Uploads имеют узкий allowlist: APK/его metadata, lint/JUnit, синтетические screenshots и свежий тестовый log. Ни .git, ни .android, ни keystore, ни домашние каталоги/все app/build целиком не загружаются. Всё содержимое будущих публичных логов/артефактов следует считать доступным посторонним.

Во всех выполняющих jobs стоит public guard. До отдельного разрешения владельца запрещены даже пробные приватные запуски; первоначальная отправка коммитов выполняется с [skip ci] и проверкой отсутствия запусков. После Public требуется отдельно разрешённый активационный коммит без этой отметки. Не делать вывод PASS из skipped private jobs.

## Предлагаемые настройки владельцу

После первого фактического полного запуска включить защиту main: изменения только через PR, обязательный **Full acceptance**, актуальный Head/ветка, отсутствие обхода проверок, запрет force push/удаления, решение владельца перед merge. GitHub может показывать имя reusable-job со своим префиксом: выбрать именно фактически зарегистрированный Full acceptance, не Quick checks.

Для внешних PR требовать ручное одобрение workflow всех сторонних участников, читать изменения .github/скриптов до запуска; минимальные read-only token permissions, запрет write tokens/secrets для fork PR. Разрешать только необходимые Actions и сохранять закрепление SHA. Эти настройки агент не изменяет. Формальная приёмка UI-01, merge и UI-02 остаются отдельными решениями.
