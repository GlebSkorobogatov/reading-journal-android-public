## 0. Цель и границы

Документ определяет проверяемые оракулы, тестовые данные, тестовые уровни, обязательные gates и отчётность. Не меняет продукт или дизайн. При конфликте с действующим PRD/дизайном/спецификацией остановить затронутый тест и согласовать решение, не переписать ожидание под реализацию. Исторические отменённые требования не тестируются как действующие. У1–У8, А1–А4, TZ-01 и точные токены обязательны. Этот план не разрешает запуск Codex, создание GitHub или написание кода.

Цель — предотвращать потерю подтверждённых данных, недостоверные время/страницы/XP и визуальные регрессии. Проверка UI на fixtures не означает проверку функций. До UI-READY — только визуальные состояния/контракты; ни реальной Room, ни таймера, ни импорта. После каждого задания — отдельный PR, проверка и явная приёмка владельцем, отдельно разрешённый merge и переход. UI-01 → UI-02 → UI-03 не объединять.

Статусы: PASS — выполнен и ожидаемое подтверждено доказательством; FAIL — фактическое расхождение; NOT RUN — не выполнялся (указать причину); N/A — проверка неприменима к данной задаче (обосновать, указать будущий этап); BLOCKED — выполнение невозможно из-за зависимости/среды, не PASS. PARTIAL не заменяет статусы отдельных проверок. Нулевое число тестов, skipped обязательного кейса и отсутствие свидетельства не считаются PASS. Flaky-тест расследовать, повторный зелёный запуск не стирает первый FAIL. Не ослаблять assertion или обновлять эталон ради зелёного CI. Регрессии и обязательные FAIL/NOT RUN/BLOCKED блокируют соответствующий gate. Дополнительный неприоритетный дефект допускает отдельное решение владельца только при отсутствии нарушения обязательных требований; документировать, не исключать молча. Не вводить произвольный процент покрытия как критерий готовности: матрица требований и риски важнее; каждый пропущенный ID требует объяснения.

## 3. Среда, fixtures и воспроизводимость

- Изолированная тестовая БД/файлы, тестовые книги и обложки, не реальные личные данные. Clean install и upgrade — отдельные сценарии; удалять только тестовую копию. На A55 перед destructive испытанием использовать синтетическую историю; после появления резервирования проверить копию. Для старых версий — migration fixtures, не destructive fallback.
- Fake Clock и независимый monotonic source, именованные зоны `Asia/Yekaterinburg`, `UTC`, `Europe/Berlin`, фиксированные даты. DST-пары Berlin 29.03.2026 (23 ч) и 25.10.2026 (25 ч); проверять с актуальными правилами tzdb, фиксировать версию. 29.02.2024, конец месяца/года, полночь и границы окон. Не использовать реальные ожидания в unit-тестах. A55 реальные испытания измерять внешним секундомером; записывать погрешность/условия, не обещать точность после force-stop.
- Fixtures: EMPTY (нет книг), LIB (дубликаты, длинная кириллица, теги, все статусы, изображения и заглушки), CYCLE (два завершённых и один текущий цикл), PAGES (перекрытие, pending/unknown, точная/месяц/год/unknown дата), TIMER (running/paused/recovery), CAL (полночь/DST/неполные интервалы), XP (все четыре источника, 15 порогов, отменённые и удалённые личные награды), BACKUP (полный состав, настройки/lock, A1/A2, Unicode и управляющие Markdown символы, оригинальные обложки только локально). Фикстуры общие, версии фиксировать; независимый oracle не вызывает production calculator для получения expected.
- UI матрица: светлая и тёмная; системная смена; обычный и увеличенный системный текст (проверить также максимальный на устройстве), портрет/альбом, клавиатура и insets, reduced motion, TalkBack; пусто/ноль/неизвестно/PENDING/ошибка/успех, длинное название, множество элементов, реальный размер A55. Не считать всё декартово произведение обязательным для каждого маленького PR: основные комбинации по scope, все критические на UI-READY/QA-02; записать фактически проверенные параметры.
- Снимки: фиксировать тему, locale, fontScale, размер, плотность и состояние, SHA. Сравнивать содержимое и токены; не использовать случайные сетевые картинки/текущую дату для эталонов. Допуск рендеринга обосновать в UI-01; не скрывать обрезание или неверный цвет. Эталон меняется только после явной приёмки. Не выдавать Preview за A55.

### TC-01 / AC-01 — Первый запуск и обычный возврат из фона

**Требование:** NAV, TIME; Холодный вход с иконки открывает Главную; возврат в книгу из дочернего экрана сохраняет контекст; при новом входе из библиотеки Чтение сверху

**Этап / уровень:** UI-04/F-07/F-15; Compose + A55.

**Действия и данные:** Открыть книгу из библиотеки; прокрутить каждую вкладку до разных элементов; перейти в редактор и назад; повернуть, свернуть, разблокировать; выйти в библиотеку, снова открыть; холодный запуск с иконки.

**Ожидаемо:** Внутри посещения восстановлены вкладка/якорь и шапка; новое посещение — Чтение сверху с развёрнутой шапкой; холодный запуск — Главная. Уведомление таймера проверять отдельно.

**Статус:** NOT RUN.

## 9. Дефекты, регрессия и отчёт

| Приоритет | Пример | Действие |
|---|---|---|
| Blocker | Потеря/частичная замена БД, неверный XP/время/страницы, недостоверное восстановление, crash основного маршрута, утечка личных данных, отсутствующий обязательный тест | Немедленно остановить gate, воспроизвести на fixture, исправить отдельным узким PR и повторить проверки |
| Major | Несоблюдение обязательной функции, сломанная навигация, недоступное действие при fontScale, несовпадение утверждённого дизайна, серьёзная регрессия | Блокирует соответствующий gate до исправления |
| Minor | Косметический недочёт без нарушения утверждённого требования | Документировать; только явное решение владельца о допустимости отсрочки |

Регрессия: после исправления — исходный failing case, соседние границы, связанные AC/риски, вся доступная CI-suite. При миграциях проверить предыдущую и обновлённую схемы и реальный APK upgrade. При изменении вычислителя повторить всю матрицу страницы/календарь/XP. При изменении UI токенов (только по отдельному согласованию) — все эталоны обеих тем. При падении в CI не скрывать вывод, не снимать тест без объяснения. Не использовать пользовательскую библиотеку для fault injection.

Шаблон отчёта (для `docs/acceptance/`, заполнить фактическими данными):

| Case ID / PRD ID | Команда или шаг | Expected | Actual | PASS/FAIL/NOT RUN/N/A/BLOCKED | Доказательство |
